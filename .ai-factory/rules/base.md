# Базовые правила проекта

> Автоматически определенные соглашения по текущей кодовой базе. Правьте этот файл при изменении архитектурных или стилевых решений.

## Именование

- Файлы: PHP-классы в `PascalCase.php`; конфигурационные и data-файлы допускают `lowercase.php`.
- Пространства имен: соответствуют PSR-4 маппингу из `composer.json` и директории файла.
- Классы и enum: `PascalCase`, например `TelegramBotApi`, `StateEnum`.
- Методы и переменные: `camelCase`, например `getBotData()`, `$chatId`, `$userRepository`.
- Константы: `UPPER_SNAKE_CASE` или typed class constants, если это уже используется в классе.

## Структура модулей

- `index.php` остается composition root и текущей точкой HTTP/Telegram входа, пока рефакторинг routing не запланирован явно.
- `api/` содержит адаптеры внешних API и Telegram facade-классы.
- `handler/` содержит обработчики Telegram `Update` и не должен напрямую управлять низкоуровневыми DB-соединениями.
- `services/` содержит orchestration/use-case логику и может зависеть от API-клиентов и repository contracts.
- `repositories/` содержит доступ к данным и состояние; новые реализации должны по возможности иметь контракт в `repositories/contracts/`.
- `db/` содержит фабрики/connection singletons для инфраструктурных соединений.
- `components/telegram/` содержит построение и отправку Telegram UI-сообщений.
- `data/`, `messages/`, `img/` содержат статические данные и assets, используемые ботом.

## Обработка ошибок

- Для ошибок бизнес-доступа использовать `DomainException`, если сообщение предназначено пользователю.
- Для невалидных ответов внешних API использовать `RuntimeException` или безопасный `false/null` результат с логированием, согласно текущему контракту метода.
- В HTTP endpoints возвращать JSON и устанавливать `http_response_code()` при ошибках.
- Не показывать пользователю токены, proxy URL, DSN и внутренние stack traces.

## Логирование

- Использовать существующий helper `log_dump()` для ошибок внешних интеграций, синхронизации и диагностически важных событий.
- Логи должны быть краткими и не содержать секретов из `.env`.
- Для console-команд допустим вывод в stdout вместе с записью в лог, как в `UserSyncService`.
